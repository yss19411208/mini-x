## 確かめた手順と結果（Claude の内蔵ブラウザ。画面は 8001 番の `bun --hot server.js`）
1. B7: 同じ名前（「B3check」2 件、「dada」2 件）は同じ色、頭文字が入る → OK
2. B8: いいねを 3 回続けて押す → 数は 0→1 だけ、ハートと数がピンク（`rgb(249, 24, 128)`）、`aria-pressed="true"`、`localStorage` に id。再読み込み → ピンクのまま → OK
3. B9 すぐ届く: 画面を開いたまま、Bun の fetch で別の人としてポスト → **19 ミリ秒後**に先頭に出た。取り直しの通信は 1 回 → OK
4. B9 二重にならない: 「ライブ」のあいだ 25 秒待つ → 10 秒ごとの取り直しは 0 回 → OK
5. B9 つなぎ直し: サーバーを止める → 「つなぎ直し中…」になり、ブラウザが 3 秒ごとにつなぎ直しを試し、10 秒ごとの取り直し（予備）が動いた。サーバーを起動し直す → 再読み込みなしで「ライブ」に戻り、取り直しが 1 回 → OK
6. `bun test` → 12 pass / 0 fail
- **確かめていないこと**: ブラウザがつなぎ直しを諦めた（CLOSED）ときに自分でつなぎ直す道（サーバーがエラーの返事をしたとき）。起こし方が難しく、試していない。30 秒ごとの `: ping` が Cloudflare 越しで切断を防ぐことも、公開前なので未確認。

## 困ったこと
- 8000 番は別の作業の `bun --hot` が使っていたので、自分の画面は 8001 番で開いた。つなぎ直しを試すために `script.js` の `API` を一時的に 8001 にした（最後に 8000 に戻した）。
- `script.js` を書き換えても、`bun --hot` が配る画面のスクリプトが古いままだった（B1〜B4 と同じ現象）。サーバーを起動し直すと直った。
- 最初は色を選ぶのに 31 を掛ける混ぜ方を使ったら、サンプルの「たろう」と「はなこ」が同じ色になった。31 は 8 で割ると −1 と同じなので、8 色だと混ざり方が弱い。33 を掛ける djb2 に変えたら、3 人が 3 色に分かれた。
- Git Bash の curl で日本語をポストすると Shift_JIS で送られて文字化けした。Bun の fetch で送り直した。
