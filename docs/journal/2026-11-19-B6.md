## 判断と理由
- **型だけ足して、動きは変えない**。ただし 2 つだけ形を変えた:
  1. `readRoom(req)`: 部屋の名前を確かめる 4 行が 4 つの API に同じように書いてあり、TS にすると `room` が null かもしれない扱いでさらに長くなるので、1 つの関数にまとめた
  2. `script.ts` の `API`: 「https なら同じ場所・http なら localhost:8000」から「3000 番（`bun run index.html`）のときだけ localhost:8000、ほかは同じ場所」に。8000 番を別のサーバーが使っていて、8001 番で確かめると古いサーバーに話しかけてしまったため。同じ場所にするほうが単純で、公開先の動きは前と同じ
- **ブラウザに .ts を渡す方法**: 前もって `.js` を作る（ビルド）か、サーバーが配るときに直すかで、後者にした。ビルドの手順が増えず、本番の更新も `git pull` と再起動のままでよい。直した結果は更新時刻つきで覚えて、毎回は直さない
- **`any` を使わない**。`JSON.parse` の結果は `unknown` で受けて確かめる
- **本番に反映できなかった**: サーバーの sudo はパスワードが要る（`sudo -n true` が失敗）。AGENTS.md の決まりどおり、AI は実行せず、人間が実行するコマンドとして渡す（下の「次にやること」）
