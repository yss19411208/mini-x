### server.js：ポストを覚えて、頼まれたら返すサーバー

- `Bun.serve` でサーバーを 8000 番で立てる。`routes` は「URL と GET/POST の組み合わせ → どの関数が答えるか」の表。
  - `GET /` → `index.html` を配る（だから http://localhost:8000/ で画面が出る）
  - `GET /posts?room=部屋` → その部屋のポスト一覧を JSON で返す（`getPosts`）
  - `POST /posts?room=部屋` → 名前と本文を受け取り、新しいポストを作って保存（`createPost`）
  - `POST /posts/:id/like?room=部屋` → その id のポストの `likes` を 1 増やす（`likePost`）
  - `GET /posts/events?room=部屋` → つなぎっぱなしにして、変化を知らせる（SSE。B9 で使う）
- 保存場所は **メモリ**（`rooms` という Map。部屋の名前 → ポストの配列）。データベースは使っていないので、**サーバーを止めるとポストは消える**。
  - `globalThis.rooms` に置いているのは、`bun --hot` がファイル保存のたびに読み込み直しても、ポストを消さないため。
- 入力は必ず確かめる: 部屋名は `^[A-Za-z0-9-]{1,32}$`、名前 20 字・本文 140 字まで（絵文字を 1 字と数えるため `Array.from` で数える）、空は不可。だめなら 400 と理由を返す。1 部屋 200 件を超えたら古いものから消す（メモリを使いすぎないため）。
- `CORS_HEADERS` は、別の URL で開いた画面（`bun run index.html`）からの fetch も受け付けるための印。

### script.js：サーバーとやりとりして画面に並べる

- 先頭の `API`（サーバーの場所 `http://localhost:8000`）と `ROOM`（部屋の名前 `sample`）を、すべての fetch で使う。
- `showPosts()`: `GET /posts` で一覧を取り、`<template id="post-template">` の見本をコピーして 1 件ずつカードを作り、タイムラインに入れる。
  - 名前と本文は **`textContent`** で入れる（`innerHTML` だと、本文に書かれた HTML が動いてしまう＝XSS になるため）。
- `addPost()`: 名前と本文を `JSON.stringify` して `POST /posts` に送り、終わったら本文欄を空にして `showPosts()` で取り直す。
- `addLike(id)`: `POST /posts/{id}/like` を送って取り直す。
- 「ポストする」ボタン → `addPost`、更新ボタン → `showPosts`。ページを開いたときにも 1 回 `showPosts()`。

### なぜ「いちばん下に足す」のか
- CSS は、同じ強さの指定が 2 つあると **後に書いたほうが勝つ**。もとの `.post` や `.avatar` を消さずに、いちばん下に上書きを足したので、「何を変えたか」が 1 か所にまとまって読みやすい。
- 例外: マウスを乗せたときの `.post:hover` は `.post` より強い（クラス＋`:hover`）ので、下に足した `.post` の白い背景を上書きしてしまう。もとの色は透明なので、灰色の下地が透けてカードが灰色になった。そこで `.post:hover` も下に足し、`color-mix` で「白に紫を 4% 混ぜた色」にした。

### `--accent`（CSS 変数）を変えると何が変わるか
- `var(--accent)` を使っている所（ポストするボタン・更新ボタンの文字・名前の入力欄・「さらに表示」・投稿欄のアイコン）が、1 行の変更で全部紫になる。色を 1 か所で決めておく利点。

## 応用ミッション B1〜B4：投稿欄と自動更新（`script.js`・`index.html`・`styles.css`・`server.test.js`）

公式の答え（`advanced/`）は見ていない。手元資料 DOCS.md のヒントだけを使った。1 つのブランチ `feat/b1-b4` にまとめ、コミットはミッションごとに分けた（4 つとも `script.js` と投稿欄の同じ場所を触るので、別々のブランチだと PR どうしがぶつかるため）。

### B1 残りの文字数（`updateCharCount`・`countChars`）
- 本文の欄に `input` イベント（1 文字打つたび・消すたびに起きる）を付け、`140 - 文字数` を `#char-count` に入れる。
- 文字数は `Array.from(text).length` で数える。`text.length` だと絵文字（😀）を 2 字と数えてしまい、サーバー（`server.js` も `Array.from`）と数がずれるため。
- 0 より小さくなったら `over` クラスを付けて赤くし（`classList.toggle`）、ポストするボタンを `disabled` にする。`addPost` の中でも 140 字を超えたら送らない（ボタンを使わない Ctrl+Enter でも止めるため）。
- 最後の守りはサーバー。画面のチェックは「使いやすさ」のため、サーバーのチェックは「守る」ため（ブラウザを使わず curl で送られても断れる）。

### B2 ポストした時刻（`formatTime`）
- サーバーはポストを作るときに `createdAt`（ISO 形式の時刻の文字。例 `2026-11-19T07:02:21.000Z`）を付けている。それを `new Date()` で時刻にし、今との差を分で出す。
- 1 分未満「たった今」、1 時間未満「N分前」、1 日未満「N時間前」、それより前は「11/19 16:02」。
- 投稿カードの見本に `<time class="time">` を足し、`textContent` で入れる。`title` に日付と秒までの時刻を入れたので、マウスを乗せると正確な時刻が出る。
- 「3分前」は時間がたつと古くなるが、B4 の 10 秒ごとの更新で描き直されるので、自然に「4分前」に変わる。

### B3 Ctrl+Enter でポスト（`postByShortcut`）
- 本文の欄に `keydown`（キーが押された）イベントを付ける。`event.key === 'Enter'` で、`event.ctrlKey`（Ctrl）か `event.metaKey`（Mac の ⌘）が押されていれば `addPost()`。
- `event.preventDefault()` で、本文に改行が入るのを止める。
- `event.isComposing` が true のとき（日本語の変換中）は何もしない。変換を決める Enter でポストされないようにするため。
- `isPosting` という印を付け、送っている途中は次のポストを送らない。キーの連打で同じポストが 2 件になるのを防ぐ（試すと、3 回続けて押しても 1 件だけだった）。`finally` で、成功しても失敗しても印を戻す。

### B4 10 秒ごとの自動更新（`showPosts`・`autoReload`・`loadPosts`）
- `setInterval(autoReload, 10 * 1000)` で 10 秒ごとに一覧を取り直す。別のタブを見ているあいだ（`document.hidden`）は画面が見えないので取りに行かない（サーバーの負担を減らす）。
- **入力中の内容が消えない理由**: 取り直しで書き換えるのは `#timeline`（タイムラインの `<ul>`）の中だけ。名前・本文の入力欄には触らない。
- **同じ通信が重ならない理由**: `isLoading` という印で、一覧を取りに行っている途中かを覚えておく。途中で頼まれたら（更新ボタンの連打、ポストの直後など）すぐには送らず `reloadAgain` に「あとでもう 1 回」と覚え、終わってから 1 回だけ取り直す。捨てずに 1 回取り直すのは、ポストした直後の頼みを捨てると、自分のポストが 10 秒間出てこないため。
  - 試すと、更新ボタンを 5 回続けて押しても、通信は 2 回（最初の 1 回＋待っていた分の 1 回）で、同時に飛んでいる通信は最大 1 本だった。
- サーバーが止まっているときは `try...catch` でエラーを受け止め、画面はそのままにする。次の 10 秒後にまた試す。
- もとの `showPosts` の中身（取ってきて並べる）は `loadPosts` に名前を変え、`showPosts` は「重ならないように呼ぶ係」にした。
