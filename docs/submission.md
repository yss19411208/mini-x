【GitHubリポジトリのURL】※提出必須
https://github.com/yss19411208/mini-x
公開先: https://minix.dreamyard.cc （React 版 /react/ 、しりとり部屋 /?room=shiritori ）
（スクショ: docs/images/ に入れたものを貼る）

【取り組んだ内容・追加した機能】
応用ミッションの A1〜A6・B1〜B11 をすべて実装しました（B6 で本体を TypeScript に、B10・B11 で React 版を react/ に）。
オリジナル機能は 2 つです。
・しりとり部屋: 前のポストの最後の字から始まる、かなのことばだけポストできる部屋（サーバーが判定）
・夢のたまご: 選んだ時間になるまで中身が見えず、時間になると先頭にかえるポスト
自宅のサーバーに Cloudflare Tunnel で公開し、IP ごとの回数制限などの攻撃への備えも入れました。

【工夫した点・苦労した点】
・夢のたまごは、画面で隠すだけだと開発者ツールで読めてしまうので、かえるまではサーバーが本文を送らないようにしました。
・攻撃への備えを入れた直後、処理できる回数が 15 分の 1 に落ちました。回数の記録を毎回全部見ていたのと、部屋を消すたびに console.log していたのが原因で、記録を先頭から見て途中で止めるように直しました。負荷試験でメモリは 653MB まで増え続けていたのが 61MB で止まりました。
・公開のとき、cloudflared が別のサービスの設定を読んでしまい 404 になりました。--config を付けて直しました。そのあとも Cloudflare が 404 をキャッシュしていて、少し待つと直りました。
・アイコンの色を名前から決めるとき、31 を掛ける作り方だと「たろう」と「はなこ」が同じ色になりました。8 色で割ると 31 は −1 と同じで混ざりにくいので、33 を掛ける djb2 に変えました。
・TypeScript にしたとき、ブラウザは .ts を読めないので、サーバーが配る前に型を取り除くようにしました（ビルドの手順を増やさないため）。

【エンジニアに見てほしいポイント・質問】

3. ポストはメモリだけで、再起動すると夢のたまごも消えます。残すならどう設計するとよいでしょうか。
